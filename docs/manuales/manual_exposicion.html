Guía para la sustentación

15 minutos de demostración y 5 de preguntas

Diego Parra

2026

Antes de entrar

  1. Docker Desktop abierto.
  2. En la carpeta del proyecto: docker compose up --build.
  3. Probar que abre http://localhost:8080.
  4. Tener a la mano el navegador, una terminal en la carpeta del proyecto y el archivo docs/modelo_er.drawio.

Ojo con el reporte: las ventas de prueba son de 2026. En la sustentación el rango tiene que ser del 1 de enero de 2026 al 31 de diciembre de 2026.

Si se registra una venta de ensayo el mismo día, los números de Inicio ya no van a ser 18 y 2. No pasa nada, se dice que esa venta se hizo en el ensayo. Si se quiere dejar todo como al principio, el backup se corre al final.

Minuto 0 a 3. El problema y el modelo

Decir que el concesionario tiene sedes en Bogotá, Medellín y Cali, y que antes el inventario y las ventas estaban en hojas de cálculo. Un carro se podía vender dos veces y el precio de lista se confundía con el precio del día de la venta.

Abrir el diagrama y señalar:

  • Una sede tiene varios vendedores y varios carros. Eso es uno a muchos.
  • CARRO_PROVEEDOR es la tabla del medio entre carros y proveedores. Eso es muchos a muchos, y ahí queda el costo de esa compra.
  • Una venta es de un cliente, un vendedor y un solo carro. El carro no se repite.
  • USUARIO es para entrar a la página. AUDITORIA la llena el trigger. No son tablas del negocio.

Si preguntan por la tercera forma normal: el teléfono de la sede no está copiado en el vendedor. El monto de la venta sí se guarda, porque es el precio de ese día.

Minuto 3 a 7. La página

Entrar como admin / admin123. En el ingreso se puede pulsar la tarjeta. Mostrar Inicio: 18 disponibles, 2 vendidos, 20 clientes, $150.000.000.

Ir a Clientes y agregar uno con una cédula que no exista, por ejemplo 1020999001. Decir que la cédula no se puede repetir.

Salir y entrar como vendedor / vendedor123. Ir a Ventas, Agregar. Elegir el cliente nuevo, a Pedro Perez, el Chevrolet Onix y Contado. Decir que el precio no se escribe: lo toma el procedimiento sp_registrar_venta. Guardar. En Vehículos, el Onix tiene que quedar Vendido. Eso lo hace el trigger, no el formulario. Mostrar que el vendedor no tiene botón Eliminar y que no le aparece Auditoría.

Salir y entrar como consulta / consulta123. No debe salir Agregar. Abrir Reporte con las fechas de 2026. Arriba están las tres ciudades. Abajo está el detalle, incluida la venta que se acaba de hacer. Decir que el detalle lo devuelve sp_reporte_ventas y el resumen lo lee de la vista vw_ventas_por_sede.

Minuto 7 a 11. MySQL

Dejar el navegador y en la terminal, desde la carpeta del proyecto, correr:

./base_de_datos/demo_permisos.sh

Consulta intenta insertar un cliente y MySQL responde 1142. Después intenta registrar una venta y responde 1370. La página ya no lo dejaba. La base tampoco, porque Flask entra con consulta_concesionario, no con root.

Si preguntan por el REVOKE: al vendedor se le dio permiso de borrar ventas y de anularlas, y en el mismo script se le quitó. Por eso anular una venta le da 1370.

./base_de_datos/demo_procedimiento.sh

El vendedor llama sp_registrar_venta. El procedimiento abre la transacción, inserta y confirma. El trigger marca el carro vendido y escribe en AUDITORIA. Si se intenta vender otra vez el mismo carro, el trigger lo rechaza. El mensaje empieza por «Trigger:».

Aclarar las dos cuentas. vendedor entra a la página. vendedor_concesionario entra a MySQL. No son la misma clave.

Minuto 11 a 13. El backup

./base_de_datos/demo_backup.sh --confirmar

El script muestra las ventas, las borra y el conteo queda en cero. Luego restaura el archivo y las ventas de prueba vuelven. Se hizo con mysqldump. Trae las rutinas y los triggers. No trae los usuarios de MySQL. Esos están en 06_usuarios.sql.

Conviene correr esto al final, porque deja otra vez las dos ventas de mayo y el Onix vuelve a Disponible.

Minuto 13 a 15. El EXPLAIN

./base_de_datos/demo_explain.sh

En VENTA el plan ya usa idx_venta_fecha, porque el reporte filtra por fecha. Para ver el antes y el después, el script arma una tabla de 5000 filas. Sin índice el plan dice ALL y recorre las 5000. Con el índice baja a unas 6. Al terminar, esa tabla se borra. No se queda en la base del concesionario.

Si preguntan por qué no hay otro índice en la cédula o en el chasis: ya son únicos, y MySQL también indexa las llaves foráneas. Poner el mismo índice otra vez solo haría más lentos los insert.

Preguntas que pueden hacer

PreguntaRespuesta
¿Qué diferencia hay entre vista, procedimiento y trigger?La vista solo lee. El procedimiento hace el trabajo cuando se llama: toma el precio e inserta la venta. El trigger corre solo en cada insert o delete de VENTA, aunque nadie llame al procedimiento.
¿Por qué el trigger puede cambiar el carro y el vendedor no?El procedimiento usa los permisos de quien lo llama. El trigger lo creó root, entonces sí puede hacer UPDATE en CARROS. El vendedor no tiene ese permiso y no lo necesita.
¿Por qué BEGIN dentro del procedimiento no abre la transacción?Ahí BEGIN abre el bloque. La transacción se abre con START TRANSACTION. En demo_transaccion.sql, que está por fuera, BEGIN sí es la transacción.
¿Por qué las dos ventas iniciales no están en auditoría?Los datos se cargan antes de crear el trigger. El trigger solo ve lo que pasa después.
¿Dónde están las claves?No están escritas en app.py. La plantilla vacía es app/backend/config.example.env. Para la demo, Docker las pasa por variables. La página nunca entra como root.
¿Cómo se evita la inyección SQL?Los valores van con %s. PyMySQL manda el dato aparte del texto del SQL.
¿Por qué Flask y no una API con React?El trabajo pide conexión directa a la base. El navegador no puede abrir MySQL. Flask arma el HTML en el servidor y desde ahí sí se conecta.
¿Qué es el chasis?Es el número único del carro. En la base la columna se llama VIN. En la pantalla se llama Chasis para que se entienda.
¿El backup trae los usuarios?No. Trae tablas, datos, vistas, procedimientos y triggers. Los usuarios se crean con 06_usuarios.sql.

Si algo falla en el momento

  • Si la página no abre, revisar que Docker esté prendido y que la dirección sea el puerto 8080, no el 5000.
  • Si el reporte sale vacío, revisar que el año sea 2026.
  • Si el Onix ya está vendido, elegir otro carro disponible, por ejemplo el Sandero o el Spark.
  • Si la consola no conecta, usar -h 127.0.0.1 y el puerto 3307. Los scripts de la carpeta base_de_datos ya lo hacen así.
