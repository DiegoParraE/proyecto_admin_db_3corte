La base se llama concesionario_db y corre en MySQL 8.4. La página la hace Flask. No hay una API en el medio: el navegador le pide la página a Flask y Flask abre MySQL con PyMySQL.

4. Vistas, procedimientos y triggers

La vista no guarda filas. Es una consulta con nombre. Las tres se ejecutan con los permisos de quien pregunta, no con los de root.

  • vw_detalle_ventas junta la venta con el cliente, el vendedor, el carro y la sede.
  • vw_inventario_disponible muestra solo los carros disponibles.
  • vw_ventas_por_sede suma lo vendido en cada ciudad.

Los procedimientos:

  • sp_registrar_venta revisa el pago, toma el precio del carro, inserta la venta y confirma. Si algo falla, deshace.
  • sp_anular_venta borra la venta. Si no existía, avisa y deshace.
  • sp_reporte_ventas devuelve las ventas entre dos fechas.

Dentro de un procedimiento, BEGIN abre el bloque de código, no la transacción. Por eso ahí se usa START TRANSACTION.

Los triggers corren solos, aunque nadie llame al procedimiento:

  • Antes de insertar, rechaza la venta si el carro no está disponible.
  • Después de insertar, marca el carro como Vendido y escribe en AUDITORIA.
  • Después de borrar, deja el carro otra vez Disponible y también escribe en AUDITORIA.

El trigger lo crea root. Por eso puede cambiar el estado del carro aunque el vendedor no tenga permiso de UPDATE sobre CARROS.

6. Índices

No se volvió a indexar la cédula ni el chasis, porque ya son UNIQUE. InnoDB también indexa las llaves foráneas.

  • idx_venta_fecha lo usa el reporte, que filtra por fecha.
  • idx_carro_estado_marca empieza por el estado, porque en la pantalla se puede filtrar solo por Disponible o Vendido.
  • idx_cliente_apellido sirve para buscar por apellido.
  • idx_manto_fecha sirve para buscar servicios de taller por fecha.

7. Cómo está montado

Docker tiene dos servicios. MySQL queda en el puerto 3307 de la máquina, porque el 3306 ya lo usa otro MySQL. La página queda en el 8080, porque el 5000 lo usa AirPlay. Adentro de Docker, MySQL sigue en 3306 y Flask en 5000.

La primera vez se ejecutan los scripts del 01 al 07. Si se vuelve a levantar, no se vuelven a correr. Para empezar de cero: docker compose down -v y después docker compose up --build.

Las pantallas están en app/frontend/templates y el estilo en app/frontend/static/style.css. El Python está en app/backend/app.py.

8. Cómo mostrar cada cosa en MySQL

Con Docker ya prendido, desde la carpeta del proyecto:

./base_de_datos/demo_permisos.sh
./base_de_datos/demo_procedimiento.sh
./base_de_datos/demo_transaccion.sh
./base_de_datos/demo_explain.sh
./base_de_datos/demo_backup.sh --confirmar

demo_permisos.sh tiene que mostrar el error 1142 cuando consulta intenta insertar, y el 1370 cuando intenta registrar una venta. demo_backup.sh pide --confirmar porque borra las ventas antes de restaurarlas.

El backup no trae los usuarios de MySQL. Esos se crean con 06_usuarios.sql. En este mismo servidor no hace falta volver a crearlos, porque siguen ahí.
